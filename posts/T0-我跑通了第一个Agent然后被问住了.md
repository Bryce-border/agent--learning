# 我跑通了第一个 Agent，然后被问住了

上周五，评审会。

我把我折腾了两周的「周报助手」投到大屏上：它能联网搜资料、翻内部文档，最后把周报草稿用邮件发到组里。演示很顺，一路绿灯，连一次重试都没有。我心里已经开始组织获奖感言了。

然后对面问了三个问题：

1. 它的成功率是多少？
2. 你上周改过 prompt，改完是变好了还是变坏了？
3. 刚才那封邮件，你怎么保证它每次都只发给组里这几个人？

我张口结舌。demo 跑了十几次没翻车，这算证据吗？改完 prompt 之后我感觉"好像顺了一点"，感觉能写进评审材料吗？至于第三个问题——我甚至没想过要去查它的发送记录。

说白了，我会搭 Agent，但我完全不知道它行不行。这个合集就是从这份尴尬里长出来的。

## 这个合集讲什么

一句话：**教你怎么判断一个 Agent 好不好、坏在哪、改了有没有用。**

讲 Agent 开发的文章一抓一大把，讲评测的少，讲得能让新手照着做的更少。多数人卡在同一个位置：demo 跑得欢，一被追问就只能说"我感觉还行"。这个合集要做的事情，就是把"我感觉"换成一套能跑、能算、能拿去汇报的东西——评测数据集怎么攒、指标怎么选、跑两次结果不一样怎么办、开放式任务拿什么判分、线上翻车了怎么捞回离线环境里复现。

顺便说个我当时也踩过的误区。我一开始以为评测就是"跑一批题、数对了几个"，后来才发现这只覆盖了最好对付的那部分。Agent 跟普通问答模型不一样：它要多步执行，会调工具，工具还有副作用——邮件发出去是撤不回的。答案全对、顺手把邮件抄送全公司，这算成功还是失败？这个问题会在 T4 专门掰扯。

那这个合集具体能给你什么？跑完之后你手上会有四样东西：一套自己攒的评测题（不是抄来的排行榜），一张能报给老板的指标表，一个给开放式任务打分的裁判系统，外加一条防止 Agent 悄悄变差的回归流水线。到 P 系列收尾时，这四样会拼成一个完整框架，代码全部开源。

## 适合谁，不适合谁

**适合你，如果：**

- 会用 Python 调大模型 API，跑过哪怕一个玩具 Agent；
- 听过 Benchmark（基准测试，用标准化任务和规则衡量能力的一套东西）、Judge（裁判模型，用大模型给输出打分）、Trace（执行轨迹，一次运行里每次模型调用和工具调用的完整记录）这些词，但没串起来过；
- 手上有一个要交付的 Agent，需要向别人证明它可用——或者马上要有。

**可能不适合你，如果：**

- 你还没写过任何 Agent，连 tool calling 都没跑通过。先去找个教程把第一个跑起来，这篇不会教你搭；
- 你要的是某个评测框架的 API 手册。合集正文只用纯标准库加自建 client 讲原理，框架横评放在番外 F1；
- 你要的是学术论文综述。涉及方法的地方我会讲清楚为什么这么做，但不复述原文。

为什么不直接用现成框架开课？因为框架把最关键的判断藏在了默认值里：Rubric（评分细则，每个维度怎么给分的标准）它替你写好了，统计它替你算完了，你连"这个数字为什么可信"都答不上来。先徒手做一遍，再去用框架，你才知道它帮你省了什么、又悄悄替你决定了什么。

**需要什么基础：** Python 能写脚本、调过任意一家大模型 API，够了。

**不需要什么基础：** 不需要数学底子。统计那篇（T11）最多讲到看懂置信区间（Confidence Interval，估计值的不确定性范围）在说什么，用抛硬币和抽卡的类比顶上去。也不需要读过论文。

## 全系列一张地图

35 篇看着吓人，其实就一条暗线。我给你画成路标：

```
跑通 Demo → 被问住（你现在大概在这）
  ↓
看看别人怎么测 → 把别人的题改成自己的 → 发现"答案对"不等于"事办成了"
  ↓
定义成功 → 选指标 → 跑出第一张结果表 → 发现两次跑的不一样
  ↓ 【这个差异是真的还是运气？】
统计算清楚 → 发现开放式任务没法用规则判对错
  ↓
让模型当裁判 → 给裁判纠偏 → 发现裁判本身也得是个系统
  ↓ 【分数低了，然后呢？】
看 Trace 破案 → 故意把工具搞坏 → 算成本、查安全、测它会不会拒绝
  ↓ 【改完之后】
别让它悄悄变差 → 上线闭环 → 报告写给人看
  ↓
最后：把前面所有零件拼成一个能用的评测框架
```

注意中间那两处【】。它们是这个系列真正的分水岭：第一处之前你在"跑评测"，之后你才开始"信评测"；第二处之前你在"打分"，之后你才开始"找原因"。急着翻目录的时候，先想自己在哪一段。

## 更新节奏和代码仓库

一周两篇，按 T0/TA → T1/T2 → T3 一路往下排，大约四个月更完正文，番外穿插着发。大体节奏是：头两周发地基四篇，然后依次走完见世面攒题、统计可靠性、Judge 全套、归因与工程指标、上线闭环，最后 P 系列实战收尾。TA 和 F2 是长期更新篇，不在这个节奏里——术语有变动、读者报新坑，随时插队。

跟读建议：别囤。每篇末尾都有动手产出，当周花一小时跟着做完，比攒到三十篇再一口气补要管用得多——评测这东西，手感是跑出来的。

所有代码都在这个仓库，按篇号分目录：

**https://github.com/Bryce-border/agent-test-learing**

代码统一 Python，模型调用封在一个可替换的 `llm_client` 里，不绑死任何一家 SDK——你换成自己用的那家，改几行就能跑。所有"发邮件、删数据"这类不可逆操作一律走 mock，默认不真发，放心跑。

全系列用一个贯穿案例：就是开头那个倒霉的「周报助手」。它会一路被测、被打分、被搞破坏、被送上灰度——T8 跑出第一张丢人的结果表，T14 被裁判偏心坑一次，T22 被我把搜索工具故意掐掉，T27 上线当天翻车。到 P 系列收尾时，它会有一套完整的评测框架护身。你可以全程拿自己的 Agent 跟着做，步骤完全一样。
